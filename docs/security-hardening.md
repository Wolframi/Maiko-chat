# Защита API и Socket.IO

## Проверка отчёта 23 октября 2026

Публичный поиск и проигрывание рингтонов из отчёта подтвердились по исходникам. Теперь каталог, аудио и исходник требуют действительной сессии `x-pulse-token`, включая `HEAD`; токен не передаётся в URL. Ответы имеют `private, no-store`, чтобы общий HTTP-кеш не обходил проверку входа. Браузер получает аудио авторизованным `fetch`, проигрывает Blob и освобождает его URL при остановке. Клиентский кеш разделён по сессиям, объединяет одинаковые загрузки и ограничен 16 МиБ / 20 клипами.

Утверждение отчёта об отсутствии любых квот было неточным: уже существовали IP-лимиты 80/90 запросов в минуту и локальный кеш клипов 64 МиБ. Усиление добавляет ограничения на аккаунт: каталог — 30/мин, клипы — 30/мин и 120/час, исходники — 6/мин и 30/час. IP-бюджет в минуту втрое больше пользовательского. Адрес определяется общей функцией с доверием только к локальному настроенному прокси. При превышении возвращается `429` с оставшимся временем `Retry-After`.

На процесс разрешены 4 одновременных поиска, 2 загрузки исходников и 2 задачи обработки клипов с очередью максимум 4. Дополнительные задачи получают `503`. Новые скачивания аудио ограничены 60/час на процесс, внешние поиски — 120/мин. Готовые клипы по-прежнему используются повторно; варианты URL YouTube нормализуются до ID записи, параметр `v` обозначает версию формата кеша, а не отдельную запись.

Для всех новых файлов кеша действуют ограничения размера, TTL и вытеснение по времени последнего чтения: клипы — 64 МиБ, исходники — 128 МиБ, страницы — 4 МиБ, метаданные — 1 МиБ. TTL страниц — 20 минут, остальных файлов — 7 дней. Новые записи кеша больше не размножаются в S3; существующие облачные копии читаются для совместимости и автоматически не удаляются. Пользовательские загруженные рингтоны и вложения эти ограничения не затрагивают.

`chats:pin` и раньше проверял аккаунт до поиска чата и не давал анонимного доступа. Исправлена неоднозначная ошибка: без сессии теперь возвращается «Сначала войдите», отдельно от отсутствующего чата. Авторизованный пользователь по-прежнему обязан быть участником.

Лимиты входа, восстановления сессии и попыток регистрации разделены. Вход: 8 попыток/мин на пару IP + логин и 60/мин на IP, восстановление: 120/мин на IP, попытки регистрации с корректными полями: 12/мин на IP. Формат проверяется до квот и scrypt. Пустые поля и занятые имена больше не расходуют часовую квоту создания аккаунтов; действуют прежние пределы 3 новых аккаунта/мин и 10/час на IP, 30/час на процесс. Окна фиксированные: отклонённые запросы не продлевают блокировку. CAPTCHA/PoW не добавлялись; лимиты успешных регистраций остаются общими для NAT.

Проверки выполняются на отдельных временных данных: отрицательные и положительные HTTP/Socket.IO сценарии, отзыв сессии, GET/HEAD, квоты, TTL/LRU, отмена загрузки и смена аккаунта. Браузерный сценарий запускается командой `cd site && node --import tsx tests/run-ringtone-browser.ts`; рабочие аккаунты и MongoDB не используются.

## Push

Разрешены HTTPS endpoint-ы FCM (`fcm.googleapis.com`), Mozilla (`updates.push.services.mozilla.com`), Apple (`web.push.apple.com`) и WNS (`*.notify.windows.com`, один поддомен). Произвольные домены, порты, URL с логином/паролем и фрагментом запрещены. Новые и сохранённые подписки проверяются перед отправкой. HTTPS-agent проверяет реальные DNS-ответы при создании соединения и запрещает внутренние, служебные и не глобальные адреса; проверка отдельно до подключения не используется. `web-push` не следует HTTP-редиректам. Параллельная доставка и время ожидания ограничены.

## Сообщения и регистрация

Сохраняется лимит 60 сообщений в минуту на аккаунт. Добавлены короткие лимиты, 120 операций с сообщениями в минуту на комнату, общий предел 300 в минуту и бюджет доставки 6000 получателям в минуту. Ожидающие подтверждения операции ограничены двумя на аккаунт и 64 на процесс. Избыточные запросы отвергаются до проверки MongoDB и записи. Группы по-прежнему ограничены 50 участниками; общий fan-out одной операции — 256 получателями/соединениями. Медленные клиенты отключаются при переполнении очереди и получают историю при повторном входе. Записи MongoDB объединяют промежуточные состояния и не создают отдельную очередь задач на каждое событие.

Метрика `[messages:load]` раз в минуту содержит число принятых/отклонённых операций, ожидающих подтверждения и среднее `msgPerSecond`. В неё входят изменения сообщений, а не только новый текст. Это журнал для внешнего мониторинга; оповещения в инфраструктуре отдельно не настроены.

Регистрация в этом проекте выполняется через Socket.IO `auth:register`: не более 3 созданных аккаунтов в минуту и 10 в час на IP, 30 в час на процесс. Лимиты общие для переподключений. Заголовки адреса клиента учитываются только при `TRUST_PROXY=1` и TCP-подключении от loopback-прокси. Nginx должен перезаписывать `X-Real-IP`. Лимиты хранятся в памяти одного процесса; для нескольких процессов потребуется общее хранилище. CAPTCHA не добавлялась.

## Медиа, GIF и поиск

Все `/uploads/` требуют корректных `sig` и `exp`, включая картинки, видео, аватары, `HEAD`, диапазоны, waveform и миниатюры. Проверка выполняется до обращения к S3 и выдачи `304`. Ответы приватные и не сохраняются браузером. Старые ссылки без подписи перестанут открываться; приложение получает подписанные URL из истории и профилей. Сроки подписей: вложения — 7 дней, аватары — 90 дней.

GIF обслуживается собственным HTTP-сервером, использующим актуальную сессию Socket.IO. Next-only маршрут закрыт. Клиент передаёт `x-pulse-token`; есть лимит на аккаунт/IP, общий лимит внешнего API, 4 параллельных запроса, объединение одинаковых запросов, валидация параметров, ограничение размера ответа и кэш не более 128 записей по 64 КиБ. Клиентский кэш также ограничен.

Пустой или односимвольный поиск групп не возвращает каталог. Выдача ограничена 30 публичными группами. Поиск людей требует 2–64 символа и возвращает максимум 20 результатов без себя, bio, online и lastSeenAt. Пустой `people:suggest` возвращает максимум 12 существующих контактов. Клиент использует отдельное событие присутствия для статуса известных контактов.

## TURN: настройка перед публикацией на другом сервере

API больше не выдаёт статичные TURN-реквизиты и не использует общедоступный relay как запасной вариант. Нужен общий случайный секрет не короче 32 символов в `site/.turn-auth-secret` (права 600) либо `TURN_AUTH_SECRET`. Тот же секрет задаётся в coturn:

```ini
use-auth-secret
static-auth-secret=REPLACE_WITH_SAME_RANDOM_SECRET
```

Удалите статические `user=...` и конфликтующую явную настройку `lt-cred-mech`, сохраните сетевые/TLS-настройки и проверьте конфигурацию coturn. Для установленного LiveKit 1.13.5 внешние TURN-серверы в `rtc.turn_servers` используют `secret_file` с путём к тому же секрету и `ttl: 600`; старые `username`/`credential` удаляются. На рабочем сервере согласованно обновлены все три сохранённые конфигурации LiveKit, в том числе реально используемая службой `/root/pulse-chat/.livekit-server.yaml`. Поддержка этих параметров проверена по [исходникам LiveKit 1.13.5](https://github.com/livekit/livekit/blob/v1.13.5/pkg/config/config.go).

После обновления на рабочем сервере проверена передача пакетов через relay по UDP, TCP и TLS: по 6 полученных пакетов, без потерь. Просроченные временные реквизиты и старая статичная пара отклоняются. Полный звонок между двумя внешними сетями после публикации не проверялся. При переносе на другой сервер отдельно проверьте такой звонок и доступность портов извне. Если секрета нет, `/api/ice` возвращает 503; клиент может использовать STUN, но связь через NAT не гарантируется.

Временный username содержит срок действия и хэш пользователя/сессии с отдельной случайной частью; пароль — HMAC-SHA1. TTL — 10 минут. Секрет и исходный токен сессии клиентам не передаются. У stateless TURN REST credentials выход из аккаунта не отзывает уже выданную пару мгновенно: она остаётся действительной до TTL. Схема следует [документации coturn](https://github.com/coturn/coturn/blob/master/README.turnserver).

## CSP и health

В production inline-скрипты разрешены только с индивидуальным nonce. `unsafe-inline` и `unsafe-eval` убраны из `script-src`; `wasm-unsafe-eval` оставлен для WebAssembly шумоподавления. В разработке `unsafe-eval` нужен инструментам Next.js. Страницы рендерятся динамически для корректных nonce. Inline-стили пока разрешены для существующего UI.

Публичный health возвращает только `ok` и признак совместимости `desktopMediaHost`. `service`, `bootId`, режимы хранилищ скрыты; `buildId` доступен только с действительной сессией, поскольку используется обновлением открытых вкладок. События `app:boot` также используются механизмом обновления интерфейса; это не секреты авторизации.

## Проверка

```bash
npm --prefix site test
npm --prefix desktop test
npm --prefix site run build
cd site
node --import tsx --test tests/http-security.integration.ts
```

Интеграционный тест требует готовой production-сборки, создаёт отдельную временную копию с вымышленными пользователями, данными и ключами, запускает сервер на свободном loopback-порту и удаляет копию после остановки. Рабочая MongoDB не используется. Проверка миграции и восстановления на настоящей MongoDB в существующем тесте `message-store.test.ts` требует `TEST_MONGODB_URI`; без неё этот тест пропускается.

В браузере на отдельной production-копии проверены вход, загрузка и отправка картинки, отображение подписанных аватаров и галереи. Для одного изображения `HEAD` с корректной подписью возвращал 200, без подписи и с поддельной — 403. Ошибок CSP при входе и работе чата не было.

При публикации на сервере прошли 56 тестов, production-сборка, TypeScript, отдельный сценарий HTTP/Socket.IO и тест MongoDB на изолированном процессе с собственным временным каталогом данных. После публикации API и подписи медиа проверены как напрямую, так и через публичный HTTPS-адрес. Авторизованный GIF-запрос вернул 200 и результат, без сессии — 401. Экран входа в публичном браузере загрузился без ошибок и предупреждений. Все 584 записи сообщений совпали с копией до переключения; сохранены 10 аккаунтов и 16 чатов. Рабочие API-ключи сохранены; TURN переведён на новый общий секрет для временных реквизитов.
