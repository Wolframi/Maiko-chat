# Голос и звонки как Discord

Два клиента, одна визуальная система.

| | Групповой канал | Личный звонок |
|---|---|---|
| Хук | `useVoiceChannel` | `useCall` |
| UI | `VoiceOverlay` + `VoiceDock` | `CallOverlay` |
| Транспорт | свой LiveKit SFU на ВМ | P2P (`RTCPeerConnection`) |
| Signalling | `voice:*` | `call:*` |

Оба оверлея ставят сцену `call__stage--discord`.

## Стиль сцены (Discord)

CSS: `src/app/globals.css` → `.call__stage--discord`.

```
┌─────────────────────────────────────────┬──────────┐
│  call__main-area                        │ rail     │
│  пусто: «участники справа»              │ камеры / │
│  или демонстрация экрана (1 или 2)      │ аватары  │
│  фон #0a0a0c                            │ 232px    │
└─────────────────────────────────────────┴──────────┘
           call__bar: mute · deafen · NS · cam · screen · leave
```

- Фон сцены `#111214`, как Discord dark.
- Сетка: `minmax(0,1fr) 232px`.
- Без шаринга — слева плейсхолдер с названием канала, люди только в рейле.
- С шарингом — экран(ы) в `call__screens`; два экрана — две колонки.
- Тайл: видео или аватар. Класс `is-speaking` — зелёное кольцо.
- Камера помечена `contentHint: "motion"`, экран `"detail"` — чтобы отличить треки в одном `MediaStream`.
- Свёрнутый канал: не прячется, а становится **Voice dock** внизу сайдбара (mute / deafen / leave / развернуть) — как нижняя панель Discord.

Личный звонок использует ту же сцену плюс индикатор сети (пинг и цвет качества связи) и ринг.

Индикатор соединения показывает `Пинг: N мс`: RTT до собеседника в личном звонке и до медиасервера в групповом канале. Цвет полосок по-прежнему учитывает качество связи. До первого измерения отображается `Пинг: —`; подключение, восстановление и потеря связи показываются отдельными статусами. Закрытие выбора экрана (в том числе кнопкой «Отмена», Escape или закрытием окна Electron) не показывает ошибку демонстрации и не меняет текущий звонок. Проверка Electron: `npm --prefix desktop run test:capture-cancel`.

Подробный разбор того, **как Discord рисует участников и момент «Calling…» до accept** (и как это сопоставлено с Pulse): [discord-call-ui.md](./discord-call-ui.md).

## Управление как в Discord

| Кнопка | Действие |
|---|---|
| Микрофон | `track.enabled = false`, событие `voice:mute`; unmute снимает deafen |
| Наушники (deafen) | глушит входящие `<audio>` и мутит себя; undeafen снова включает микрофон |
| Шумоподавление | кнопка-звезда: DTLN → браузерный NS |
| Камера | отдельный `getUserMedia({ video })`; в ЛС можно вместе с экраном |
| Экран | `getDisplayMedia`, до 1440p / 30 fps и 8 Mbps при хорошем соединении |
| Повесить | `voice:leave` / конец call |

Deafen на сервере форсирует `muted: true` и `speaking: false`, чтобы в списке канала сразу был перечёркнутый микрофон.

Камера в канале стартует выключенной (как Discord). В 1:1 — тоже mic-first: видео по кнопке.

## Топология: P2P в ЛС, SFU в группах

Сервер — источник истины (`server.ts`): голосовой канал группы **всегда** `sfu`. Личные звонки в эту карту не попадают.

```
Личный звонок (ЛС)     →  P2P WebRTC (`useCall`)
Голосовой канал группы →  свой LiveKit SFU на этой ВМ (`useVoiceChannel` → LiveKit)
```

LiveKit Cloud не используется: URL `*.livekit.cloud` сервер отбрасывает. Локально без `.livekit-*` файлов Pulse берёт `ws://127.0.0.1:7880` и ключи `devkey` / `secret` (`livekit-server --dev`).

```bash
livekit-server --dev
npm run dev
```

На прод-ВМ: `bash scripts/setup-livekit-vps.sh` (LiveKit на `127.0.0.1:7880`, снаружи `wss://<хост>/livekit` через nginx).

Если SFU не поднялся, клиент **выходит из канала** с ошибкой, а не остаётся «в канале без звука».

## P2P (только личные звонки)

`useCall.ts`:

- На пира — свой `RTCPeerConnection`.
- Offer/answer/ICE через `call:signal`.
- ICE: `/api/ice` → STUN + TURN (`src/lib/iceServers.ts`).
- Видео: `replaceTrack` / `attachLocalVideoTrackByHint`, камера и экран вместе.
- Камера до 1080p / 3 Mbps, экран до 1440p / 30 fps / 8 Mbps.
- При средней сети экран сохраняет разрешение, снижая частоту до 15 fps; при слабой сети уменьшается и разрешение. Переход ведущего в другую вкладку не снижает качество экрана.
- Opus: голос до 96 kbps, звук демонстрации — стерео до 192 kbps / 48 кГц без речевого шумоподавления. Аудио имеет приоритет перед видео. Эти лимиты общие для личных звонков и LiveKit; фактические параметры зависят от источника и сети.

Проверка качества: `npx playwright test e2e/screen-quality.spec.ts e2e/screen-audio-routing.spec.ts e2e/call-media.spec.ts --workers=1` из `site`. Проверяются получение кадров 2560×1440, восстановление bitrate/fps после изменения сети, сохранение качества экрана в фоновой вкладке и раздельные стереоканалы после декодирования. Для `call-media.spec.ts` нужен локальный `npm run dev` с демо-аккаунтами; первые два файла используют изолированные синтетические источники, без захвата рабочего стола.

`voice:signal` для группового канала сервер не пропускает (топология всегда `sfu`).

## LiveKit (SFU, только группы)

1. Клиент уже в `voice:join`.
2. `POST /api/livekit/token` `{ channelId }` → JWT на 1 час, `identity = userId`.
3. `Room.connect(serverUrl, token)`, публикация mic / camera / screenshare.
4. Комната на SFU: `liveKitRoomName(channelId)`, max 12 участников, empty timeout 300 с.

Секреты: `.livekit-url`, `.livekit-api-key`, `.livekit-api-secret` (или env). Health: `GET /api/health/livekit`.

## Шумоподавление

Слой [src/lib/noiseFilter.ts](../site/src/lib/noiseFilter.ts) обрабатывает исходящий микрофон личных и групповых звонков.

- **DTLN**: две квантованные модели через закреплённый пакет `@workadventure/noise-suppression@0.1.1`. Вычисления идут локально в отдельном Worker (LiteRT/WASM), AudioWorklet отвечает только за непрерывную выдачу звука, без отправки звука в сторонние сервисы. ScriptProcessor не используется.
- Модель работает на **16 кГц, моно**: Web Audio пересчитывает частоту микрофона. Полоса речи ограничена 8 кГц; это режим для речи, не для музыки.
- Контекст фильтра отдельный, поэтому частота общего контекста LiveKit не влияет на модель. Модель добавляет 24 мс задержки, буфер между Worker и AudioWorklet — ещё 64 мс (итого 88 мс сверх захвата/передачи). Обходной сигнал выровнен по этой задержке; переход занимает 25 мс. Запоздавшие блоки отбрасываются по номеру. Короткий пропуск плавно затухает от последнего обработанного сэмпла, не подставляя необработанный шум микрофона. Очередь ограничена 8 блоками. При длительной перегрузке остаётся браузерный NS.
- Переключение сохраняет микрофон и выходной трек, не перепубликует их. Модель загружается только при первом включении и сохраняется до завершения сессии. В режиме обхода блоки не отправляются Worker, поэтому нейросеть не расходует CPU. При повторном включении состояние модели сбрасывается; переход начинается только после появления обработанных блоков.
- При ошибке загрузки или исполнения — плавный обход и браузерный NS с уведомлением. При завершении завершается Worker, освобождаются worklet, выходной трек и собственный AudioContext. LiveKit сохраняет владение исходным микрофоном.

Эхоподавление и автогромкость остаются в браузере. Браузерный NS работает перед DTLN: это дополнительная обработка коротких шумов, в том числе во время загрузки модели и пропуска запоздавшего блока Worker. Режим `off` отключает оба шумоподавителя. Индикатор микрофона в настройках измеряет обработанный сигнал и реагирует на переключение DTLN. Сохранённый ключ `pulse-krisp` оставлен для совместимости настроек; в интерфейсе фильтр называется DTLN.

`npm run audio:prepare` собирает Worker, копирует AudioWorklet, модели и WASM из установленного пакета в `public/audio/dtln-0.1.1` (около 13 МБ без сжатия). Команда автоматически выполняется перед dev/build/start. Файлы генерируются локально, не скачиваются с CDN в звонке и не коммитятся. При обновлении пакета нужно синхронно обновить путь в `dtlnGraph.ts` и повторить аудиотесты.

Проверка: `npm run audio:prepare`, затем `npx playwright test e2e/noise-filter.spec.ts --workers=1` (Microsoft Edge). Тестовый сервер сам раздаёт настоящие модели и AudioWorklet, сервер Next.js не требуется. Проверяются постоянный шум, синтетические щелчки и удары, задержка Worker, индикатор настроек, непрерывность при переключениях/нагрузке UI, fallback, mute, restart LiveKit и cleanup. Проверка субъективного качества речи и слабых устройств проводится отдельно реальным звонком.

Голосовые сообщения сейчас используют собственный захват без фильтра (`VoiceRecorderBar`).

Источники: [DTLN и модели](https://github.com/breizhn/DTLN), [браузерная реализация](https://github.com/workadventure/noise-suppression). Старый пакет Krisp удалён: его интеграция рассчитана на LiveKit Cloud, а приложение использует свой SFU и P2P.

## Индикатор «говорит»

**1:1:** `AnalyserNode`, FFT 256, средний уровень по бинам. Порог **> 18**, удержание **320 мс**. Свой тайл тоже подсвечивается.

**SFU:** `RoomEvent.ActiveSpeakersChanged` от LiveKit, плюс `voice:speaking` на сервер.

Сервер кладёт флаг в `VoiceMember` и рассылает `voice:state`. UI: кольцо на аватаре в оверлее и в списке канала.

## ICE / NAT

`src/lib/iceServers.ts`:

1. Google STUN, STUN хоста, TURN UDP/TCP/TLS если заданы `TURN_USER` / `TURN_PASS`.
2. Иначе публичный Open Relay (запасной).
3. Cloudflare STUN.

Клиент кэширует ответ `/api/ice`. Без TURN звонки через симметричный NAT часто не соберутся — на проде TURN обязателен (тот же, что прописывается в LiveKit yaml).

## Конфликты и устойчивость

- Один пользователь = один голосовой канал **или** один 1:1 звонок.
- Новая вкладка выгоняет старую (`voice:kick` / takeover).
- Обрыв сокета: 12 с на reconnect, затем leave.
- После `connect` клиент сам делает `voice:join` повторно.

## Медиа-хелперы

`src/lib/webrtcMedia.ts` — общие constraints и разбор «это камера или экран»: `displaySurface`, `facingMode`, `contentHint`, label. Нужно, потому что в одном `MediaStream` живут mic + cam + screen, а сцена Discord показывает их в разных слотах.
