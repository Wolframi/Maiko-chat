# Обновления приложения Windows

Исходники и выпуски: [Wolframi/Maiko-chat](https://github.com/Wolframi/Maiko-chat). Обновления использует `electron-updater` 6.8.10; установщик — electron-builder 26.15.3, NSIS x64.

Приложение проверяет стабильные релизы через 20 секунд после запуска и каждые 6 часов. В верхней панели постоянно видна текущая версия. Кнопка «Проверить» запускает проверку, «Обновить» скачивает новую версию и предупреждает об автоматическом перезапуске. При скачивании показываются проценты, а мессенджер остаётся доступным. После скачивания появляется «Установка…»: сохраняются настройки окна, сбрасываются на диск cookies и локальное хранилище, останавливается принадлежащий приложению локальный сервер. Затем вызывается `quitAndInstall(true, true)`: NSIS работает тихо и запускает приложение через `--force-run` только после замены файлов. `app.relaunch()` и таймер запуска не используются, поэтому обычный путь обновления не открывает старую версию до завершения установки. Перезагрузка сайта перед установкой убрана, чтобы сократить паузу. Вход и настройки окна сохраняются в профиле `Maiko`. Ошибку подготовки или запуска установки можно повторить без повторного скачивания; автоматические проверки не сбрасывают ожидающее установки обновление. Резервная установка при обычном закрытии остаётся включённой (`autoInstallOnAppQuit=true`), но такой выход не открывает приложение повторно (`autoRunAppAfterInstall=false`).

Обновляются установленные версии **Maiko-Setup**. При запуске из исходников обновления отключены. Старый EXE без механизма обновления нужно один раз заменить установщиком нового выпуска. Готовое приложение подключается к закреплённому адресу Майко; ввод адреса и старые пользовательские адреса отключены.

## Новый выпуск

1. Изменить `version` в `desktop/package.json` и обновить lockfile: `npm install --package-lock-only --ignore-scripts --prefix desktop`.
2. Обновить `desktop/release-notes.md`.
3. Выполнить проверки и отправить коммит в GitHub.
4. Создать тег, совпадающий с версией, например `git tag v1.1.9`, затем `git push origin v1.1.9`.

Workflow `.github/workflows/desktop-release.yml` проверяет тег, запускает тесты, собирает Windows-приложение и проверяет SHA-512 установщика. Создаёт черновик, загружает все файлы и только затем публикует релиз. Workflow не перезаписывает существующий релиз: для исправлений нужна новая версия.

После выпуска отдельное задание публикует файлы на сервер обновлений. Для него
настроены секреты `MAIKO_RELEASE_SSH_KEY` и `MAIKO_RELEASE_HOST_KEY`. Ключ сервера
закреплён, а ключ публикации разрешает только запуск `scripts/publish-desktop-feed.py`
через stdin. Скрипт принимает три файла, проверяет размер, SHA-512 и версию,
сохраняет старые установщики и атомарно публикует `latest.yml` последним.

Начиная с 1.1.12 нативный менеджер скачиваний передаёт прогресс изолированному
помощнику страницы. В сообщении показывается такое же круговое оформление,
как при отправке файла: процент считается по полученным байтам, нажатие отменяет
скачивание, завершение или ошибка возвращает обычную иконку. Удалённая страница
не получает доступ к папкам и путям на диске; API помощника доступен только в
изолированном мире Electron.

Файлы каждого релиза: `Maiko-Setup-<version>.exe`, его `.blockmap` и `latest.yml`. Portable больше не собирается и не публикуется. Метаданные установщика нужны для обнаружения и проверки обновлений. Исходники и копии релизов хранятся в приватном GitHub. Клиент получает обновления без токена через `https://maiko.galacticvps.qzz.io/desktop-updates/` (generic HTTPS provider). Файлы обслуживает Nginx из `/var/www/maiko-desktop-updates/`. После выпуска скопируйте установщик и blockmap, затем атомарно замените `latest.yml`: метаданные публикуются последними, когда все файлы уже доступны. В CI токен GitHub не добавляется в приложение.

Версия 1.1.9 использовала GitHub feed, недоступный без авторизации из-за приватности репозитория. Её нужно один раз заменить новым установщиком. После проверки актуальной версии кнопка показывает «Обновлено». В версиях 1.1.11–1.1.12 «Готово» означало перезагрузку интерфейса, а EXE устанавливался при обычном закрытии. При быстром ручном запуске установка могла ещё не завершиться. Начиная с 1.1.13 установщик сам запускает новую версию после установки, а текущий номер версии меняется только в новом процессе.

Проверка перехода между версиями: установить предыдущий выпуск с новым механизмом, опубликовать следующую версию, нажать «Проверить» → «Обновить». Проверить, что во время скачивания окно остаётся доступным, после скачивания появляется «Установка…», приложение автоматически закрывается и открывается уже с новой версией, а вход и настройки окна сохраняются. Unit-тесты покрывают порядок подготовки и установки, флаги тихой установки и запуска после завершения, запрет двойного запуска, ошибки и повторные попытки. Electron UI-тест использует настоящий контроллер с подменённым установщиком, проверяет отображение и отсутствие лишней перезагрузки сайта. Реальная замена EXE и длительность паузы проверяются отдельно на установленном приложении.
