# Обновления приложения Windows

Исходники и выпуски: [Wolframi/Maiko-chat](https://github.com/Wolframi/Maiko-chat). Обновления использует `electron-updater` 6.8.10; установщик — electron-builder 26.15.3, NSIS x64.

Приложение проверяет стабильные релизы через 20 секунд после запуска и каждые 6 часов. В верхней панели рядом с кнопками окна постоянно видна текущая версия. Кнопка «Проверить» запускает проверку, «Обновить» скачивает новую версию, «Установить» перезапускает приложение для установки. Во время проверки и скачивания вращается индикатор; скачивание показывает проценты и полосу прогресса. Подробности доступны при наведении. Ошибки позволяют повторить попытку. Фоновое закрытие приложения не устанавливает обновление без нажатия кнопки. Перед установкой останавливается принадлежащий приложению локальный сервер. Вход и настройки окна сохраняются в прежнем профиле `Maiko`.

Обновляются установленные версии **Maiko-Setup**. При запуске из исходников обновления отключены. Старый EXE без механизма обновления нужно один раз заменить установщиком нового выпуска. Готовое приложение подключается к закреплённому адресу Майко; ввод адреса и старые пользовательские адреса отключены.

## Новый выпуск

1. Изменить `version` в `desktop/package.json` и обновить lockfile: `npm install --package-lock-only --ignore-scripts --prefix desktop`.
2. Обновить `desktop/release-notes.md`.
3. Выполнить проверки и отправить коммит в GitHub.
4. Создать тег, совпадающий с версией, например `git tag v1.1.9`, затем `git push origin v1.1.9`.

Workflow `.github/workflows/desktop-release.yml` проверяет тег, запускает тесты, собирает Windows-приложение и проверяет SHA-512 установщика. Создаёт черновик, загружает все файлы и только затем публикует релиз. Workflow не перезаписывает существующий релиз: для исправлений нужна новая версия.

Файлы каждого релиза: `Maiko-Setup-<version>.exe`, его `.blockmap` и `latest.yml`. Portable больше не собирается и не публикуется. Метаданные установщика нужны для обнаружения и проверки обновлений. Токен GitHub используется только в CI; клиент читает публичные Releases без токена. Источник обновлений зафиксирован в сборке.

Проверка перехода между версиями: установить предыдущий выпуск с обновлениями, опубликовать следующую версию, в верхней панели нажать «Проверить» → «Обновить» → «Установить». Убедиться, что версия изменилась, а вход и настройки окна сохранились. Unit-тесты покрывают состояния, ошибки, повторные попытки, конкурирующие команды и остановку сервера; окончательный переход между двумя установленными версиями проверяется отдельно.
