# Обновления приложения Windows

Актуальный выпуск от 23 октября 2026 года — **1.1.26**. При обычном запуске модель
показывается не менее пяти секунд с первого кадра, даже при мгновенной загрузке
сайта. Сайт загружается параллельно; уменьшение движения и ошибка модели пропускают
ожидание. При перезапуске после установки вторая заставка не добавляется.

Основной код приложения
защищён байткодом Bytenode, скрипты интерфейса обфусцированы, CSS-классы локальных
окон переименованы. Включён защищённый фронтенд сайта без публичных source maps.
Проверены публикация S3 и настоящее автоматическое обновление установленной
1.1.25 до 1.1.26, включая NSIS и запуск новой версии. Подробности защиты:
[code-protection.md](code-protection.md). Все предыдущие изменения сайта,
медиасессии, качества связи и адаптивной вёрстки сохранены.

Убраны боковые полосы окна;
при запуске показывается локальная модель без повторной заставки сайта. Обновление
автоматически устанавливается после скачивания и запускает новую версию; смену
процессов закрывает отдельное окно с локальной анимацией. Сайт обновлён вместе
с приложением; подробности проверок — в [журнале публикаций](deployment.md).

Кнопка **«Скачать VST3»**
находится справа в нижней строке окна выбора экрана или приложения, на одном уровне
с кнопками отмены и демонстрации. Рядом подпись **«Для передачи звука DAW такие как FL studio»**.
Нажатие автоматически устанавливает только VST3 в пользовательскую папку
`%LOCALAPPDATA%\Programs\Common\VST3`, без ZIP и дополнительных файлов в загрузках.
После проверки установленной версии кнопка заменяется на **«✓ Установлено»**;
состояние проверяется при каждом открытии окна. Если старый плагин занят в DAW,
закройте DAW и повторите установку. Настройка сканирования: [инструкция](daw-audio.md).

В редакторе VST3 заголовок **«Майко / Мост DAW»**, индикатор сигнала и шкалы L/R.
Звук DAW подхватывается автоматически по выбранному экрану или приложению;
VST подключается и во время демонстрации без её перезапуска.

Внизу левой колонки групп на сайте находится кнопка «Скачать Майко для Windows».
Адрес `/desktop-updates-s3/latest.exe` определяет актуальный установщик по опубликованному
манифесту `latest.yml` и перенаправляет скачивание в S3. Ответ не кешируется, поэтому
после публикации нового выпуска кнопка автоматически скачивает новую версию.

Исходники и выпуски: [Wolframi/Maiko-chat](https://github.com/Wolframi/Maiko-chat). Обновления использует `electron-updater` 6.8.10; установщик — electron-builder 26.15.3, NSIS x64.

Приложение проверяет стабильные релизы при запуске и каждые 30 минут. Найденное при запуске обновление автоматически скачивается и устанавливается. Во время работы кнопка «Обновить» запускает скачивание, установку и автоматический запуск новой версии без второго нажатия. При обычном закрытии приложения установка не запускается (`autoInstallOnAppQuit=false`).

В верхней панели постоянно видна текущая версия. «Обновить» скачивает новую версию в фоне с отображением процентов. После проверки скачивания сохраняются размеры окна, cookies и локальное хранилище, затем подготавливается отдельное окно с локальной анимацией модели. Только после подтверждения, что оно уже нарисовано, вызывается `quitAndInstall(true, true)`. Остановка принадлежащего приложению локального сервера выполняется в `before-quit`, чтобы ошибка подготовки не останавливала работающий интерфейс. NSIS работает тихо и запускает новую версию через `--force-run` после замены файлов. `app.relaunch()` и таймер запуска EXE не используются. Ошибку установки можно повторить без скачивания; автоматические проверки сохраняют скачанное обновление. Кнопки отдельного перезапуска нет.

`update-handoff.cjs` копирует `native/update-window.exe` и нужный файл модели в отдельную сессию `%APPDATA%/Maiko/update-handoff/`, вне каталога установки. Вспомогательный процесс не удерживает EXE, DLL или `app.asar`, поэтому переживает завершение старой версии и не мешает NSIS. `native/maiko-animation.cs` рисует ту же локальную модель из частиц с её костной анимацией; полосы загрузки нет. Если анимация уже шла при запуске, передаётся её текущее время и участок танца. После одного прохода сохраняется последняя поза, без повторного запуска заставки.

Новая версия распознаёт сессию по номеру версии, случайному токену и живому вспомогательному процессу. Она загружает интерфейс под этим окном и не проигрывает собственную заставку повторно. После готовности интерфейса и отрисовки кадра приложение показывает новое окно, подтверждает завершение, закрывает вспомогательное окно и удаляет временные файлы. Ошибка подготовки оставляет прежнее приложение доступным. Вход и размеры окна сохраняются. Замена EXE и загрузка интерфейса всё ещё занимают время; на протяжении этого перехода остаётся окно с моделью.

При запуске вместо отдельной карточки «Почти на месте» показывается одна локальная анимация модели. `prepare-assets.cjs` собирает общий с сайтом рендерер в `ui/startup-model.js`; обе модели находятся в `bundled-assets/models/`. Доступ к их байтам разрешён только локальной оболочке через ограниченный IPC. Сервер не нужен для показа анимации. Маркер `maiko-desktop-startup` включает ожидание готовности интерфейса: приложение сохраняет локальную анимацию до сигнала от чата. Вложенная страница в приложении не запускает свою анимацию и не ждёт полного танца; в обычном браузере заставка сохраняется. Ошибки соединения по-прежнему показывают кнопки повтора и журнала.

Обновляются установленные версии **Maiko-Setup**. При запуске из исходников обновления отключены. Старый EXE без механизма обновления нужно один раз заменить установщиком нового выпуска. Готовое приложение подключается к закреплённому адресу Майко; ввод адреса и старые пользовательские адреса отключены.

## Новый выпуск

1. Изменить `version` в `desktop/package.json` и обновить lockfile: `npm install --package-lock-only --ignore-scripts --prefix desktop`.
2. Обновить `desktop/release-notes.md`.
3. Выполнить проверки и отправить коммит в GitHub.
4. Создать тег, совпадающий с версией, например `git tag v1.1.9`, затем `git push origin v1.1.9`.

Workflow `.github/workflows/desktop-release.yml` проверяет тег, запускает тесты, собирает Windows-приложение и проверяет SHA-512 установщика. Создаёт черновик, загружает все файлы и только затем публикует релиз. Workflow не перезаписывает существующий релиз: для исправлений нужна новая версия.

После выпуска отдельное задание публикует файлы в закрытый S3 и переходный серверный канал. Для него
настроены секреты `MAIKO_RELEASE_SSH_KEY` и `MAIKO_RELEASE_HOST_KEY`. Ключ сервера
закреплён, а ключ публикации разрешает только запуск `scripts/publish-desktop-feed.py`
через stdin. Скрипт принимает три файла, проверяет размер, SHA-512 и версию,
проверяет чтением обратно установщик и blockmap в S3 и публикует `latest.yml` последним.

## Переход на S3 с 1.1.14

Приложение проверяет обновления сразу при запуске и каждые 30 минут. Backend
также рассылает `desktop:update-available` всем соединениям Socket.IO и нативным
клиентам в namespace `/desktop-updates` через существующий `/api/socket`.
После успешной публикации обоих каналов скрипт атомарно обновляет
`site/data/desktop-release.json`; сервер отправляет уведомление в течение секунды.
При подключении или переподключении клиент получает актуальную опубликованную
версию. Уведомление запускает обычную проверку закреплённого канала обновлений;
скачивание остаётся по кнопке «Обновить».

Версия 1.1.14 — переходная: старый адрес `/desktop-updates/` остаётся на ней.
После её установки приложение использует `/desktop-updates-s3/`. Сервер выдаёт
метаданные из S3 и временные ссылки на установщики и blockmap; байты файлов,
включая запросы Range для обновлений по блокам, идут напрямую из Cloud.ru.
Старые установщики и blockmap сохраняются в `desktop-updates/` бакета `maiko`.
Бакет остаётся закрытым.

Отдельная конфигурация `site/.desktop-s3-storage.json` исключена из Git и сборки Electron:
поля `endpoint`, `region`, `bucket`, `accessKeyId` (`tenant_id:key_id`) и `secretAccessKey`.
На сервере файл имеет права `600`. Можно указать `DESKTOP_S3_CONFIG_FILE`.
Настройки медиа в `.s3-storage.json` не меняются.

Публикация выполняется `scripts/publish-desktop-feed.py` под блокировкой. Он
запускает `site/scripts/publish-desktop-s3.ts`, а для 1.1.14 также обновляет старый
серверный канал. Для версий выше 1.1.14 публикуется только S3; старый канал
остаётся на переходной версии. Недоступность S3 прерывает публикацию.

## Подпись и контроль установки

Используется `electron-updater` 6.8.10. Проверка запускается автоматически или
кнопкой «Проверить»; при запуске скачивание начинается автоматически, а во время
работы — по «Обновить». Оно работает в фоне; после
успешного скачивания автоматически подготавливается окно с моделью и вызывается `quitAndInstall(true, true)`. Обновления по блокам
включены; при их недоступности библиотека скачивает полный установщик.

Сейчас сертификата подписи нет: установщик проверяется по SHA-512 из манифеста.
Это не проверка издателя и не защита при подмене файла вместе с манифестом.
Для Authenticode нужно настроить секреты CI `WIN_CSC_LINK` и
`WIN_CSC_KEY_PASSWORD` и выпустить подписанную версию. Electron-builder записывает
издателя сертификата в `app-update.yml`; установленная подписанная версия затем
отклоняет обновления с неподходящей подписью. Отключение проверки подписи в коде
не используется. Ошибка проверки скачивания не вызывает установку.

Начиная с 1.1.12 нативный менеджер скачиваний передаёт прогресс изолированному
помощнику страницы. В сообщении показывается такое же круговое оформление,
как при отправке файла: процент считается по полученным байтам, нажатие отменяет
скачивание, завершение или ошибка возвращает обычную иконку. Удалённая страница
не получает доступ к папкам и путям на диске; API помощника доступен только в
изолированном мире Electron.

Файлы каждого релиза: `Maiko-Setup-<version>.exe`, его `.blockmap` и `latest.yml`. Portable не собирается. Метаданные установщика нужны для обнаружения и проверки обновлений. Исходники и копии релизов хранятся в приватном GitHub. Используется generic HTTPS provider без токена GitHub в приложении. Nginx из `/var/www/maiko-desktop-updates/` обслуживает переходную версию; новые установщики скачиваются из S3.

Версия 1.1.9 использовала GitHub feed, недоступный без авторизации из-за приватности репозитория. Её нужно один раз заменить новым установщиком. После проверки актуальной версии кнопка показывает «Обновлено». В версиях 1.1.11–1.1.12 «Готово» означало перезагрузку интерфейса, а EXE устанавливался при обычном закрытии. При быстром ручном запуске установка могла ещё не завершиться. Начиная с 1.1.13 установщик сам запускает новую версию после установки, а текущий номер версии меняется только в новом процессе.

Проверка перехода между версиями: опубликовать следующую версию и запустить установленное приложение либо нажать «Обновить» во время работы. После скачивания установка начинается сама, во время замены файлов показывается локальная модель, затем появляется готовый интерфейс новой версии. Проверить сохранение входа и размеров окна, отсутствие второго нажатия и повторной заставки, ошибки скачивания и повтор установки. Unit-тесты покрывают порядок подготовки и установки, отмену и восстановление окна. `test:update-handoff` проверяет настоящий вспомогательный EXE: он переживает завершение старого Electron, продолжает анимировать модель при задержанном ответе сервера новой версии и закрывается после отрисовки её интерфейса. Установщик в этой проверке не запускается. `test:updates-ui` проверяет автоматическую установку и отсутствие кнопки перезапуска с подменённым установщиком. Реальная замена файлов NSIS проверяется отдельно на установленном приложении.
