# Обновления приложения Windows

Исходники и выпуски: [Wolframi/Maiko-chat](https://github.com/Wolframi/Maiko-chat). Обновления использует `electron-updater` 6.8.10; установщик — electron-builder 26.15.3, NSIS x64.

Приложение проверяет стабильные релизы при запуске и каждые 30 минут. В верхней панели постоянно видна текущая версия. Кнопка «Проверить» запускает проверку, «Обновить» скачивает новую версию и предупреждает об автоматическом перезапуске. При скачивании показываются проценты, а мессенджер остаётся доступным. После скачивания появляется «Установка…»: сохраняются настройки окна, сбрасываются на диск cookies и локальное хранилище, останавливается принадлежащий приложению локальный сервер. Затем вызывается `quitAndInstall(true, true)`: NSIS работает тихо и запускает приложение через `--force-run` только после замены файлов. `app.relaunch()` и таймер запуска не используются, поэтому обычный путь обновления не открывает старую версию до завершения установки. Перезагрузка сайта перед установкой убрана, чтобы сократить паузу. Вход и настройки окна сохраняются в профиле `Maiko`. Ошибку подготовки или запуска установки можно повторить без повторного скачивания; автоматические проверки не сбрасывают ожидающее установки обновление. Резервная установка при обычном закрытии остаётся включённой (`autoInstallOnAppQuit=true`), но такой выход не открывает приложение повторно (`autoRunAppAfterInstall=false`).

Обновляются установленные версии **Maiko-Setup**. При запуске из исходников обновления отключены. Старый EXE без механизма обновления нужно один раз заменить установщиком нового выпуска. Готовое приложение подключается к закреплённому адресу Майко; ввод адреса и старые пользовательские адреса отключены.

## Новый выпуск

1. Изменить `version` в `desktop/package.json` и обновить lockfile: `npm install --package-lock-only --ignore-scripts --prefix desktop`.
2. Обновить `desktop/release-notes.md`.
3. Выполнить проверки и отправить коммит в GitHub.
4. Создать тег, совпадающий с версией, например `git tag v1.1.9`, затем `git push origin v1.1.9`.

Workflow `.github/workflows/desktop-release.yml` проверяет тег, запускает тесты, собирает Windows-приложение и проверяет SHA-512 установщика. Создаёт черновик, загружает все файлы и только затем публикует релиз. Workflow не перезаписывает существующий релиз: для исправлений нужна новая версия.

После выпуска отдельное задание публикует файлы в закрытый S3 и переходный серверный канал. Для него
настроены секреты `MAIKO_RELEASE_SSH_KEY` и `MAIKO_RELEASE_HOST_KEY`. Ключ сервера
закреплён, а ключ публикации разрешает только запуск `scripts/publish-desktop-feed.py`
через stdin. Скрипт принимает три файла, проверяет размер, SHA-512 и версию,
проверяет чтением обратно установщик и blockmap в S3 и публикует `latest.yml` последним.

## Переход на S3 с 1.1.14

Приложение проверяет обновления сразу при запуске и каждые 30 минут. Backend
также рассылает `desktop:update-available` всем соединениям Socket.IO и нативным
клиентам в namespace `/desktop-updates` через существующий `/api/socket`.
После успешной публикации обоих каналов скрипт атомарно обновляет
`site/data/desktop-release.json`; сервер отправляет уведомление в течение секунды.
При подключении или переподключении клиент получает актуальную опубликованную
версию. Уведомление запускает обычную проверку закреплённого канала обновлений;
скачивание остаётся по кнопке «Обновить».

Версия 1.1.14 — переходная: старый адрес `/desktop-updates/` остаётся на ней.
После её установки приложение использует `/desktop-updates-s3/`. Сервер выдаёт
метаданные из S3 и временные ссылки на установщики и blockmap; байты файлов,
включая запросы Range для обновлений по блокам, идут напрямую из Cloud.ru.
Старые установщики и blockmap сохраняются в `desktop-updates/` бакета `maiko`.
Бакет остаётся закрытым.

Отдельная конфигурация `site/.desktop-s3-storage.json` исключена из Git и сборки Electron:
поля `endpoint`, `region`, `bucket`, `accessKeyId` (`tenant_id:key_id`) и `secretAccessKey`.
На сервере файл имеет права `600`. Можно указать `DESKTOP_S3_CONFIG_FILE`.
Настройки медиа в `.s3-storage.json` не меняются.

Публикация выполняется `scripts/publish-desktop-feed.py` под блокировкой. Он
запускает `site/scripts/publish-desktop-s3.ts`, а для 1.1.14 также обновляет старый
серверный канал. Для версий выше 1.1.14 публикуется только S3; старый канал
остаётся на переходной версии. Недоступность S3 прерывает публикацию.

## Подпись и контроль установки

Используется `electron-updater` 6.8.10. Проверка запускается автоматически или
кнопкой «Проверить»; скачивание начинается по «Обновить», работает в фоне, после
успешной проверки вызывается `quitAndInstall(true, true)`. Обновления по блокам
включены; при их недоступности библиотека скачивает полный установщик.

Сейчас сертификата подписи нет: установщик проверяется по SHA-512 из манифеста.
Это не проверка издателя и не защита при подмене файла вместе с манифестом.
Для Authenticode нужно настроить секреты CI `WIN_CSC_LINK` и
`WIN_CSC_KEY_PASSWORD` и выпустить подписанную версию. Electron-builder записывает
издателя сертификата в `app-update.yml`; установленная подписанная версия затем
отклоняет обновления с неподходящей подписью. Отключение проверки подписи в коде
не используется. Ошибка проверки скачивания не вызывает установку.

Начиная с 1.1.12 нативный менеджер скачиваний передаёт прогресс изолированному
помощнику страницы. В сообщении показывается такое же круговое оформление,
как при отправке файла: процент считается по полученным байтам, нажатие отменяет
скачивание, завершение или ошибка возвращает обычную иконку. Удалённая страница
не получает доступ к папкам и путям на диске; API помощника доступен только в
изолированном мире Electron.

Файлы каждого релиза: `Maiko-Setup-<version>.exe`, его `.blockmap` и `latest.yml`. Portable не собирается. Метаданные установщика нужны для обнаружения и проверки обновлений. Исходники и копии релизов хранятся в приватном GitHub. Используется generic HTTPS provider без токена GitHub в приложении. Nginx из `/var/www/maiko-desktop-updates/` обслуживает переходную версию; новые установщики скачиваются из S3.

Версия 1.1.9 использовала GitHub feed, недоступный без авторизации из-за приватности репозитория. Её нужно один раз заменить новым установщиком. После проверки актуальной версии кнопка показывает «Обновлено». В версиях 1.1.11–1.1.12 «Готово» означало перезагрузку интерфейса, а EXE устанавливался при обычном закрытии. При быстром ручном запуске установка могла ещё не завершиться. Начиная с 1.1.13 установщик сам запускает новую версию после установки, а текущий номер версии меняется только в новом процессе.

Проверка перехода между версиями: установить предыдущий выпуск с новым механизмом, опубликовать следующую версию, нажать «Проверить» → «Обновить». Проверить, что во время скачивания окно остаётся доступным, после скачивания появляется «Установка…», приложение автоматически закрывается и открывается уже с новой версией, а вход и настройки окна сохраняются. Unit-тесты покрывают порядок подготовки и установки, флаги тихой установки и запуска после завершения, запрет двойного запуска, ошибки и повторные попытки. Electron UI-тест использует настоящий контроллер с подменённым установщиком, проверяет отображение и отсутствие лишней перезагрузки сайта. Реальная замена EXE и длительность паузы проверяются отдельно на установленном приложении.
