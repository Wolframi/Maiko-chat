# Обновления приложения Windows

Исходники и выпуски: [Wolframi/Maiko-chat](https://github.com/Wolframi/Maiko-chat). Обновления использует `electron-updater` 6.8.10; установщик — electron-builder 26.15.3, NSIS x64.

Приложение проверяет стабильные релизы через 20 секунд после запуска и каждые 6 часов. В настройках можно проверить вручную, скачать новую версию и перезапустить приложение для установки. Скачивание показывает прогресс; ошибки позволяют повторить попытку. Фоновое закрытие приложения не устанавливает обновление без нажатия кнопки. Перед установкой останавливается принадлежащий приложению локальный сервер. Вход, адрес сайта и настройки сохраняются в прежнем профиле `Maiko`.

Обновляются установленные версии **Maiko-Setup**. Portable и запуск из исходников показывают пояснение в настройках. Старый EXE без механизма обновления нужно один раз заменить установщиком нового выпуска.

## Новый выпуск

1. Изменить `version` в `desktop/package.json` и обновить lockfile: `npm install --package-lock-only --ignore-scripts --prefix desktop`.
2. Обновить `desktop/release-notes.md`.
3. Выполнить проверки и отправить коммит в GitHub.
4. Создать тег, совпадающий с версией, например `git tag v1.1.9`, затем `git push origin v1.1.9`.

Workflow `.github/workflows/desktop-release.yml` проверяет тег, запускает тесты, собирает Windows-приложение и проверяет SHA-512 установщика. Создаёт черновик, загружает все файлы и только затем публикует релиз. Workflow не перезаписывает существующий релиз: для исправлений нужна новая версия.

Файлы каждого релиза: `Maiko-Setup-<version>.exe`, его `.blockmap`, `Maiko-Portable-<version>.exe` и `latest.yml`. Последние два файла с метаданными установщика нужны для обнаружения и проверки обновлений. Токен GitHub используется только в CI; клиент читает публичные Releases без токена. Источник обновлений зафиксирован в сборке и не зависит от адреса сайта в настройках.

Проверка перехода между версиями: установить предыдущий выпуск с обновлениями, опубликовать следующую версию, открыть настройки → проверить → скачать → перезапустить. Убедиться, что версия изменилась, а вход и настройки сохранились. Unit-тесты покрывают состояния, ошибки, повторные попытки, конкурирующие команды и остановку сервера; окончательный переход между двумя установленными версиями проверяется отдельно.
