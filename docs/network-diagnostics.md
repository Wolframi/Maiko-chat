# Проверка доступа к Майко из другой сети

Если сайт не открывается одновременно в браузере и Electron, сначала проверьте доступ к HTTPS-серверу из этой сети. Потеря пакетов `ping` сама по себе не определяет причину: ICMP и TCP-порт 443 могут фильтроваться по-разному.

Перенесите только `Диагностика сети Майко.cmd` на компьютер, подключённый к проблемному Wi-Fi, и запустите двойным щелчком. Вся проверка встроена в один файл; дополнительные файлы, Python, Node.js и права администратора не требуются. Отчёт `Maiko-network-report.txt` сохраняется рядом с CMD. После завершения окно остаётся открытым до нажатия клавиши.

Исходник встроенной проверки находится в `scripts/Test-MaikoNetwork.ps1`. После его изменения пересоберите единый CMD:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/Build-NetworkDiagnostics.ps1
```

При отдельном запуске `Test-MaikoNetwork.ps1` отчёт по умолчанию сохраняется в `output/network-diagnostics.txt`.

Проверка выбирает активный физический адаптер с IPv4-шлюзом. Если одновременно подключены Ethernet и Wi-Fi, отключите Ethernet или явно укажите имя Wi-Fi адаптера:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/Test-MaikoNetwork.ps1 -InterfaceAlias "Wi-Fi"
```

HTTPS-сокеты привязываются к выбранному интерфейсу через Windows `IP_UNICAST_IF`, поэтому обычные маршруты TUN VPN не используются. Скрипт не меняет маршруты, VPN, настройки DNS и проверку сертификатов. Системный DNS проверяется отдельно и может использовать DNS установленного VPN; независимый запрос DNS over HTTPS к Cloudflare тоже идёт через выбранный физический интерфейс. Прокси запросам не назначается. Фильтры антивируса и драйверов на уровне Windows могут всё равно влиять на соединение.

Проверяются известный IP сервера `179.254.175.134` и адреса из системного DNS. При обращении по IP сохраняются исходное имя сайта в TLS и заголовок Host; сертификат проверяется для `maiko.galacticvps.qzz.io`. Проверяются загрузка всей HTML-страницы, `/api/health`, HTTP polling Socket.IO, WebSocket и совместимость с TLS 1.2.

| Результат | Что проверять дальше |
| --- | --- |
| Известный IP отвечает, системный DNS не отвечает или возвращает другой адрес | DNS провайдера/роутера, фильтрацию домена. Возможен обход через безопасный DNS. |
| `FAIL at TCP:443` даже для известного IP | Маршрутизацию, фильтрацию IP/порта, правила роутера и провайдера. Замена DNS это не исправляет. |
| TCP работает, `FAIL at TLS` | Точный текст ошибки сертификата, часы устройства, HTTPS-фильтрацию, MTU маршрута. |
| HTTP 200, но WebSocket не возвращает 101 | Фильтрацию WebSocket. Основной чат уже начинает с HTTP polling и затем пробует WebSocket. |
| Все проверки успешны, а браузер не открывает сайт | Прокси браузера, его безопасный DNS, расширения, антивирус и текст ошибки браузера. |

Если недоступен IP сервера, Electron без другого доступного пути к серверу тоже не сможет подключиться. Решение зависит от подтверждённой причины: другой доступный сервер/адрес, прокси или VPN. Смена DNS помогает только при проблеме DNS; отключение проверки сертификатов не является исправлением.

## Исправление HSTS 14 октября 2026

При последующей проверке обнаружены два заголовка `Strict-Transport-Security` в одном ответе: приложение отправляло `max-age=31536000; includeSubDomains`, а Nginx добавлял `max-age=31536000`. По [RFC 6797, раздел 7.1](https://www.rfc-editor.org/rfc/rfc6797.html#section-7.1) сервер должен отправлять только один такой заголовок. Объединение значений через запятую некоторыми инструментами может вызывать предупреждение о некорректной политике; конкретный источник сообщения `Server sent invalid/disabled HSTS policy` ещё не установлен.

На VPS в `/etc/nginx/sites-available/maiko` Nginx назначен единственным источником публичного HSTS:

```nginx
proxy_hide_header Strict-Transport-Security;
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
```

Заголовок добавлен также в location страницы ошибок, где собственные `add_header` отключают наследование, и согласован для `/desktop-updates/`. Существующая политика приложения не менялась. `preload` не добавлялся. При будущей замене конфигурации Nginx необходимо сохранить подавление HSTS от upstream и единый публичный заголовок.

Исходная конфигурация сохранена в `/root/maiko-backups/hsts-20261014T050831Z/maiko.before`. Перед reload выполнен `nginx -t`. Проверены единственный HSTS и ожидаемые статусы главной страницы, health, Socket.IO polling, канала обновлений и ответа 404. После изменения HTTPS и WebSocket проверены также через физический Ethernet в обход VPN.

HSTS передаётся в HTTP-ответе после установления TLS. Ошибка синтаксиса нового заголовка сама по себе не объясняет отказ на этапе TCP/TLS. Уже сохранённая браузером политика HSTS может запрещать обход ошибок сертификата, поэтому при отказе в колледже по-прежнему нужен точный текст ошибки и отчёт из той сети. Исправление дублирования не подтверждает, что причина недоступности в колледже устранена.
