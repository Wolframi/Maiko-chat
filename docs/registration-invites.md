# Приглашения в Майко

В профиле каждого зарегистрированного пользователя есть раздел **«Приглашения»**:
личный код, время до его обновления и кнопка **«Скопировать приглашение в Майко»**.
Новые участники сразу получают собственный код и тоже могут приглашать знакомых.

Код меняется каждые 7 дней относительно времени создания аккаунта. Он сохраняется
при перезапуске сервера; предыдущий код перестаёт действовать точно на границе
следующего периода. При копировании клиент запрашивает актуальный код у сервера.
Коды для регистрации и коды вступления в закрытые группы независимы.
Код вступления в группу тоже обновляется раз в неделю — в понедельник в 00:00
по Екатеринбургу. На границе недели предыдущий код перестаёт действовать.

По умолчанию для регистрации требуется код действующего участника. Проверка
выполняется сервером в `auth:register`, до хеширования пароля и расходования квоты
создания аккаунтов. Код можно вводить в любом регистре, с дефисами или без них.
У нового аккаунта сохраняется внутреннее поле `invitedBy`; публичный список людей
его не раскрывает.

В том же разделе у существующего **@Artem** есть переключатель регистрации по
приглашениям. Когда требование выключено, поле кода исчезает из формы, а регистрация
открывается для всех. При повторном включении сервер снова требует действующий
код. Уже открытые страницы получают изменение через Socket.IO. Вход существующих
пользователей не требует приглашения.

Права закреплены за ID аккаунта при первой инициализации, а не проверяются по
изменяемому никнейму. Смена ника не переносит права на другого пользователя.
Настройка, закреплённый ID и случайный серверный секрет хранятся в закрытом файле
`site/data/registration-invites.json`, который нужно включать в резервные копии.
Файл создаётся с правами `600`; его содержимое не следует публиковать или менять
при работающем сервере. Если файл повреждён, сервер отказывается запускаться.
На совершенно пустой установке администратора и первый аккаунт нужно подготовить
до первого запуска: публичного обхода приглашений для первого посетителя нет.

Проверки:

```powershell
cd site
npm test
npx tsc --noEmit
node --import tsx --test tests/registration-invites.integration.ts tests/http-security.integration.ts
npx playwright test e2e/registration-invites.spec.ts
```

Для браузерного теста нужна готовая production-сборка. Сценарий запускает отдельный
сервер с временными данными и не создаёт аккаунты на рабочем сайте. Проверяются
копирование в буфер, регистрация, личный код нового участника, отсутствие у него
переключателя, обновление режима на открытой форме, сохранение после перезагрузки
и мобильная вёрстка. Вспомогательные серверы остальных интеграционных тестов явно
используют открытую регистрацию в своих временных данных.
