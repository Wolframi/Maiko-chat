# Холодный запуск Electron и модель при обновлении

Проверено 29 октября 2026 года на Windows x64, Intel Core i5-7600,
GeForce GTX 1050 Ti, Electron 44.7.0. Каждый запуск использует новый каталог
данных приложения; кеш Windows и драйвера не очищается. Сервер стенда отвечает
мгновенно: эти числа не включают загрузку настоящего сайта по интернету.

## Что показал профиль

| Этап | Три запуска до исправления обёртки WASM | Три запуска после |
|---|---:|---:|
| Возврат конструктора окна от запуска процесса | 238–296 мс | 232–307 мс |
| Окно готово к показу | 550–1085 мс | 614–629 мс |
| Готовый интерфейс, включая 3 секунды заставки | 4294–4879 мс | 4330–4475 мс |
| Подготовка графа | JS | Rust во всех трёх |
| Рендерер / число точек | WebGL / 84 000 | WebGL / 84 000 |

Это запуски исходников. Медианы полного запуска — 4556 и 4459 мс. Разница мала относительно разброса;
это не доказательство ускорения на секунды. Прежние 20–28 секунд в этих
запусках не воспроизвелись.
Трасса Chromium показала около 200 мс на создание D3D11-устройства и
около 130–150 мс на один из синхронных запросов статуса WebGL-программы.
Эти времена относятся к наблюдавшимся быстрым запускам.

Исходные замеры: `output/electron-startup/2026-10-29T15-13-07-363Z/summary.json`
и `2026-10-29T15-21-53-483Z/summary.json`. Трасса быстрого запуска:
`2026-10-29T15-18-12-868Z/trace-1.json` в том же каталоге.

Основная задержка возникла раньше. При этом суммарное CPU-время процесса

не доказано. Текущий сеанс не запущен от администратора.

Следовательно, перенос ещё одного вычисления на Rust не устранит основную
холодную паузу. Причину медленной загрузки DLL на уровне Windows (диск,
сканирование и т. п.) эта трасса не определяет. Трасса и отчёт находятся в
`output/electron-startup/2026-10-29T15-34-17-042Z/`.

В журнале установленного приложения реальное обновление 29 октября имеет
следующие отметки UTC: запуск установщика в 13:59:09.160, первая запись нового
процесса в 14:00:07.664, подключение в 14:00:10.142, завершение перехода около
14:00:13.266. Промежуток 58,5 секунды включает установку и ранний запуск нового
процесса; старый журнал не позволяет разделить их. Ошибка `UnknownVizError`
при захвате кадра перехвачена кодом перехода и сама не доказывает зависание.

## Исправления

- Страховочные 15 секунд отсчитываются после загрузки локальной оболочки.
  Раньше создание окна и графики могло израсходовать весь таймер до первого
  кадра. Стенд задерживает оболочку на 16 секунд и проверяет последующие
  3 секунды анимации отдельно.
- Истечение 100 мс ожидания WASM больше не делает отказ постоянным.
  Фоновая загрузка может завершиться позже; подготовка графа ждёт её максимум
  100 мс от своего запроса, затем использует JS. Зависший запрос отменяется
  через 4,5 секунды. Отмена компонента не отменяет общий модуль.
- На каждой новой заставке создаётся свежий canvas. После перехода на 2D
  прежний canvas не мог снова получить WebGL-контекст: случайная ошибка
  графики оставляла последующие обновления на 14 000 точек. Теперь следующая
  попытка может восстановить 84 000; причина переключения записана в
  `data-fallback-reason` и консоль оболочки.
- Независимое окно установки использует **C#**, а не Rust/WASM. Оно сохраняет
  полные 84 000 точек, теперь учитывает глубину и рисует круглые частицы с
  размером, зависящим от DPI. Задние поверхности больше не засвечивают лицо.
  Проверка перекрывающихся передней и задней частиц защищает от регрессии.
  Чтение отсутствующих файлов сигналов больше не вызывает исключения каждый
  кадр. Это окно по-прежнему рисуется на CPU и отличается от WebGL-симуляции.

Непрерывное движение обоих танцев проверяется после 8, 9, 13 и 20 секунд при
DPI 1 и 2. В тесте перехода отдельный процесс продолжает анимацию после выхода
старого Electron и закрывается после готовности нового интерфейса.
Неизвестное зависание реального установщика этим стендом не воспроизведено;
запуск NSIS в тесте перехода имитируется.

## Повторный профиль

```powershell
npm --prefix desktop run assets
npm --prefix desktop run profile:startup -- --runs=3
npm --prefix desktop run profile:startup -- --runs=1 --trace
npm --prefix desktop run test:startup-watchdog
npm --prefix desktop run test:startup
npm --prefix desktop run test:update-handoff
```

Для проверки готовой сборки задайте `MAIKO_TEST_EXECUTABLE` абсолютным путём к
её EXE. Для профиля настоящего сайта задайте `MAIKO_PROFILE_URL`. Стенд включает
тестовый режим, поэтому не устанавливает обновления. Не запускайте одновременно
сборки и тяжёлые тесты при сравнении времени.

В `output/electron-startup/<дата>/` сохраняются JSONL событий основного процесса,
отметки загрузки модели/графа/шейдеров, фактически использованный Rust/JS,
режим графики, сведения о GPU, снимок интерфейса и итоговый JSON.
`--trace` дополнительно сохраняет трассу Chromium для Perfetto.
Профилирование основного процесса включается только переменной
`MAIKO_DESKTOP_PROFILE`; обычные запуски не пишут эти файлы.

## Проверки итоговых изменений

- 52 модульных теста Electron, включая перекрытие частиц и движение на двух DPI.
- 21 тест моделей, симуляции и точного совпадения графов Rust/JS.
- 9 браузерных тестов WASM: поздняя загрузка, ошибки, отмена, зависший запрос.
- TypeScript и ESLint изменённой обёртки и её браузерных тестов.
- Задержка оболочки на 16 секунд с сохранением трёхсекундной заставки.
- В защищённом EXE: обычный запуск, уменьшенное движение, длительное обновление
  интерфейса, принудительный Canvas-резерв и восстановление полного WebGL.
- В защищённом EXE: независимая анимация между старым и новым процессами,
  подтверждение готовности интерфейса и удаление временных файлов перехода.
- Упаковка и проверка отсутствия исходников/карт кода в защищённом архиве.
